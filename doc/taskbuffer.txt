1. INTRODUCTION                                   *taskbuffer-introduction*

taskbuffer.nvim is a Neovim plugin for managing a personal task and
time-tracking system built on Obsidian-style markdown notes. Tasks are
defined inline in `.md` files using a specific syntax, scanned with
ripgrep, parsed in Lua, and displayed in a custom read-only taskfile buffer
bucketed by date interval (Overdue, Today, Tomorrow, This Week, etc.).

==============================================================================
2. REQUIREMENTS                                   *taskbuffer-requirements*

- Neovim >= 0.10
- Linux or macOS with the standard cp utility (Windows is unvalidated)
- ripgrep (`rg`) on PATH
- Tag picker: Neovim's built-in vim.ui.select, or a configured provider

The plugin is pure Lua; there is no build step or separate taskbuffer executable.

4. CONFIGURATION                                 *taskbuffer-configuration*

Call `require("taskbuffer").setup(opts)` with a table of options. Any
option not specified falls back to its default value.

                                                   *taskbuffer-config-opts*
>lua
  require("taskbuffer").setup({
      -- State directory for current task tracking
      state_dir = "~/.local/state/task",

      -- Output directory for the legacy synchronous script export
      tmpdir = "/tmp",

      -- Whether to show undated tasks by default
      show_undated = true,

      -- Task sources: directories (recursive) or glob patterns
      sources = { "~/Notes" },

      -- Optional code annotation rules (see |taskbuffer-annotations|)
      annotations = {},

      -- Default location for new tasks
      inbox = {
          file = "~/Notes/inbox.md",
          header = nil,  -- e.g. "## Tasks"
      },

      -- Time horizons (nil = built-in defaults)
      horizons = nil,
      horizons_overlap = "sorted",
      week_start = "monday",

      -- Frontmatter configuration
      frontmatter = {
          due_key = "due",
          inherit_due = true,
          require_tags = {},
          status = {
              key = "status",
              done_values = { "done", "complete" },
          },
      },

      -- Task syntax formats
      formats = {
          date = "%Y-%m-%d",
          time = "%H:%M",
          duration = "<{n}m>",
          tag_prefix = "#",
          checkbox = {
              open = "- [ ]",
              done = "- [x]",
              irrelevant = "- [-]",
          },
          date_wrapper = { "(@[[", "]]", ")" },
          marker_prefix = "::",
      },

      -- Keymaps: set any to false to disable
      keymaps = {
          global = {
              complete        = "<leader>tc",
              defer           = "<leader>td",
              check_off       = "<leader>tx",
              irrelevant      = "<leader>ti",
              undo_irrelevant = "<leader>tu",
              note            = "<leader>ev",
          },
          taskfile = {
              start_task         = "<leader>tb",
              go_to_file         = "gf",
              irrelevant         = "<leader>ti",
              undo_irrelevant    = "<leader>tu",
              filter_tags        = "#",
              reset_filters      = "<leader>tt",
              toggle_markers     = "<leader>tj",
              toggle_undated     = "<leader>ts",
              shift_date_back    = "<M-Left>",
              shift_date_forward = "<M-Right>",
              set_date_today     = "<C-T>",
              quickfix           = "<M-C-q>",
              undo               = true,
              redo               = true,
          },
          markdown = {
              shift_date_back    = "<M-Left>",
              shift_date_forward = "<M-Right>",
              set_date_today     = "<C-T>",
          },
      },
  })
<

To disable a keymap, set it to `false`: >lua
  keymaps = { global = { note = false } }
<

                                                    *taskbuffer-horizons*
Horizons ~

Horizons control how tasks are bucketed by due date. When `horizons` is
nil (the default), the built-in horizons are used: Overdue, Today,
Tomorrow, This Week, This Month, This Year, Far Off, and Someday.

Each horizon is a table with these fields:

  `label`    (string)         Heading text, e.g. `"# Today"`
  `after`    (number|string)  Cutoff: integer day offset (0 = today),
                            duration string ("2d", "1w", "1m", "1y"),
                            or calendar keyword ("past", "yesterday",
                            "end_of_week", "end_of_month",
                            "end_of_quarter", "end_of_year")
  `undated`  (boolean)        If true, collects undated tasks
  `order`    (number|nil)     Explicit display order

Example: >lua
  require("taskbuffer").setup({
      horizons = {
          { label = "# Overdue", after = "past" },
          { label = "# Today",   after = 0 },
          { label = "# Soon",    after = "1w" },
          { label = "# Backlog", undated = true },
      },
      horizons_overlap = "sorted",
      week_start = "monday",
  })
<

`horizons_overlap` controls task placement when multiple horizons match:

  `"sorted"`       (default) Task appears in all matching horizons
  `"first_match"`  Task appears only in the first matching horizon
  `"narrowest"`    Task appears only in the narrowest matching horizon

`week_start` sets the first day of the week (default: `"monday"`).

                                                *taskbuffer-annotations*
Tasks in code ~

Sources may include multiple note directories and code projects. Annotation
rules extend task discovery without changing Markdown checkbox syntax:
>lua
  require("taskbuffer").setup({
      sources = { "~/notes", "~/projects/shop/src" },
      annotations = {
          {
              extension = "rs",
              search = "todo!",
              pattern = '^%s*todo!%s*%(%s*"(.-)"%s*%)%s*;?%s*$',
          },
      },
  })
<
`extension` is the filename extension without a dot. `search` is an rg/grep
regular expression added to the existing asynchronous discovery scan.
`pattern` is a Lua pattern whose first capture is the task text. Rules apply
only to matching extensions, after trying the configured checkbox prefixes.
Captured text supports the usual tags, dates, and duration syntax.

The example matches a standalone, single-line `todo!("description #code");`
with an optional semicolon. It is a text pattern, not a Rust syntax parser:
multiline calls, raw strings, and calls embedded in expressions need different
rules. An empty `todo!()` has no description and is not included.

Code annotations are open tasks for listing, filtering, and source navigation.
Resolve them by editing the source, then save and return to taskbuffer. Task
checkbox/date/timer mappings refuse to modify annotation rows or add Markdown
markers to code. Annotation discovery is disabled by default (`annotations = {}`).

                                                    *taskbuffer-formats*
Date and time formats ~

The `formats.date` and `formats.time` options control how dates and times
are parsed, displayed, and written throughout the plugin. Both accept
strftime-style format strings.

Supported date directives:
  `%Y`  Four-digit year (2026)
  `%m`  Two-digit month (03)
  `%d`  Two-digit day (04)
  `%F`  Shorthand for `%Y-%m-%d`

Supported time directives:
  `%H`  24-hour hour (15)
  `%M`  Minute (04)
  `%I`  12-hour hour (3)
  `%p`  AM/PM
  `%R`  Shorthand for `%H:%M`

Examples: >lua
  -- US date format with 12-hour time
  formats = {
      date = "%m/%d/%Y",
      time = "%I:%M %p",
  }
  -- Task: - [ ] Meeting (@[[03/04/2026]] 1:00 PM)

  -- European date format
  formats = {
      date = "%d.%m.%Y",
  }
  -- Task: - [ ] Meeting (@[[04.03.2026]])
<

These formats affect:
- Parsing task lines from markdown files
- Displaying dates in the taskfile buffer
- Writing `::start`, `::stop`, `::complete`, and other markers
- Date shifting (`<M-Left>`, `<M-Right>`) and set-today (`<C-T>`)
- The `defer`, `irrelevant`, and `complete-at` commands

Known limitations:
- Path-prefixed wikilinks with slash-separated dates (e.g.,
  `(@[[daily/03/04/2026]])` with `%m/%d/%Y`) are ambiguous. Use a format
  without `/` separators if you use path-prefixed wikilinks.
- Changing the date format mid-stream means existing tasks in the old
  format will not parse. Migrate existing tasks manually.

                                                  *taskbuffer-frontmatter*
Frontmatter ~

taskbuffer reads YAML frontmatter from markdown files to enrich tasks:

- Tag inheritance: Tags from the frontmatter `tags` field are merged
  with inline `#tags` on each task.
- Due date inheritance: When `inherit_due` is enabled (the default),
  undated tasks inherit the file's frontmatter due date.
- Status filtering: Files whose frontmatter status matches a
  `done_values` entry (e.g. `status: done`) are excluded from the
  task list.
- Project tasks: Files with a `project` tag and a frontmatter due
  date appear as a synthetic project task, sorted after regular tasks
  with the same date.

`require_tags` restricts due date inheritance to files with specific
frontmatter tags. For example, setting `require_tags = { "project" }`
means only files tagged `project` will inherit frontmatter due dates.

Health check ~

Run `:checkhealth taskbuffer` to verify your setup. Checks:
- Neovim version (>= 0.10)
- ripgrep is available
- Source directories exist
- vim.ui.select tag picker (no picker plugin required)

5. COMMANDS                                         *taskbuffer-commands*

                                                                   *:Tasks*
Source edits:
    Linux/macOS source writes use the standard cp utility to preserve file
    permissions, ACLs, and extended attributes in staged replacements.
    Actions from the taskfile refuse to overwrite a source buffer with unsaved
    changes. Save that buffer first. Task and date shortcuts in a Markdown
    buffer edit its current contents, including unsaved changes, and use normal
    Neovim undo. Save those changes with :write.
    If source files change, run :Tasks and wait for the refresh before acting on
    a task. Stale task locations are rejected.

    :Tasks uses a persistent, readonly scratch buffer named taskbuffer://tasks.
    Source paths, line numbers, and snapshots are stored in Lua alongside the
    visible rows. Search and yanks operate on the displayed text; paths are not
    concealed inside the lines. Opening and refreshing the list write no output
    file. The taskfile filetype and existing mappings are unchanged.

    The legacy synchronous buffer.refresh_taskfile() script helper still writes
    serialized output under tmpdir. list.list() and list.list_async() retain the
    path-prefixed text format for scripts. list.view_async() returns a table
    {lines, rows} for interactive consumers, plus the source snapshot as the
    third callback argument (the second is an optional error). Row numbers are
    1-based; headings and blank rows have no task entry. Treat returned data as
    immutable. Internal task actions use the published row table, never text
    parsed from the display.

:Tasks                  Open the taskfile buffer. Clears any active tag
                        filter and refreshes the task list.

                                                              *:TasksClear*
:TasksClear             Clear tag filters and refresh the taskfile.

                                                             *:TasksUndated*
:TasksUndated           Open the taskfile buffer with undated tasks visible,
                        regardless of the `show_undated` config setting.

6. KEYBINDINGS                                     *taskbuffer-keybindings*

All keymaps can be customized or disabled via the `keymaps` config table.

Global (all filetypes) ~

  Key               Action ~
  `<leader>tc`        Mark task on current line as complete
  `<leader>td`        Defer task on current line
  `<leader>tx`        Quick check-off (no marker)
  `<leader>ti`        Mark task irrelevant
  `<leader>tu`        Undo irrelevant
  `<leader>ev`        Insert a dated note entry

In a Markdown/source buffer, task and date shortcuts edit the current buffer,
including unsaved changes. Each task action is one normal undo step; use `u` and
`<C-r>` to undo/redo, and `:write` to save. `<leader>ti` changes `- [ ]` to `- [-]`
and adds the `::irrelevant` marker together. The task list reads saved files.

In the taskfile view, actions write to source files. Save any unsaved source
buffer first so the task list's line numbers remain safe to use.

Taskfile buffer ~

  Key               Action ~
  `<leader>tb`        Start timer for task under cursor
  `gf` / `<CR>`       Jump to source file location
  `<leader>ti`        Mark task irrelevant
  `<leader>tu`        Undo irrelevant
  `#`                 Toggle a tag filter using vim.ui.select
  `<leader>tt`        Clear all filters
  `<leader>tj`        Show/hide `::` markers
  `<leader>ts`        Toggle undated task visibility
  `<M-Left>`          Move due date earlier (accepts count)
  `<M-Right>`         Move due date later (accepts count)
  `<C-T>`             Set due date to today
  `<M-C-q>`           Send visual selection to quickfix
  `u`                 Undo last date change (auto-detect)
  `<C-r>`             Redo last date change (auto-detect)

Date shift, set today, and quickfix also work in visual mode on
multiple tasks.

Date changes keep the cursor on the selected task as it moves between groups.
After jumping to a source, <C-o> or <C-6> returns to the task list and refreshes
saved changes. :Tasks also returns and refreshes, and clears tag filters.
<C-o> and <C-6> use Neovim's normal jumplist and alternate-buffer navigation.

The tag picker uses vim.ui.select. Neovim's built-in menu works without extra
plugins; a configured vim.ui.select provider supplies its own interface. Pick a
tag to toggle it on/off; open # again to select more tags. Active tags show [x].
Use <leader>tt to clear all filters. Dismissing the picker leaves filters alone.
Telescope users can configure telescope-ui-select.nvim or another vim.ui.select
adapter; installing Telescope alone does not replace vim.ui.select.

Markdown files ~

  Key               Action ~
  `<M-Left>`          Move due date earlier (accepts count)
  `<M-Right>`         Move due date later (accepts count)
  `<C-T>`             Set due date to today

7. TASK SYNTAX                                       *taskbuffer-syntax*

Tasks are standard markdown checkboxes with optional metadata:
>
  - [ ] Task body <30m> #tag (@[[2026-02-17]] 16:00)
<

  Component     Format                      Required ~
  Checkbox      `- [ ]`, `- [x]`, `- [-]`    Yes
  Body          Free text                   Yes
  Duration      `<Nm>` (e.g. `<30m>`)         No
  Tags          `#tag-name`                   No
  Due date      `(@[[YYYY-MM-DD]])`           No
  Due time      `(@[[YYYY-MM-DD]] HH:MM)`    No

Markers ~

Markers are appended to task lines to track state changes:

  Marker                          Meaning ~
  `::start [[DATE]] TIME`           Task timer started
  `::stop [[DATE]] TIME`            Task timer stopped
  `::complete [[DATE]] TIME`        Task completed
  `::deferral [[DATE]] TIME`        Task deferred
  `::original [[DATE]]`             Original due date (on first deferral)
  `::irrelevant [[DATE]] TIME`      Marked irrelevant

Full example: >
  - [x] Write report <30m> #work (@[[2026-02-17]] 15:00) ::start [[2026-02-17]] 15:17 ::complete [[2026-02-17]] 17:19
<

8. PUBLIC API                                           *taskbuffer-api*

    Initialize the plugin with the given options. Registers autocmds and
    keymaps. See |taskbuffer-configuration| for available options.

taskbuffer.tasks()

    Called by |:Tasks|.

taskbuffer.tasks_clear()

                                                *taskbuffer.source_args()*
taskbuffer.source_args()
    Returns a list of CLI arguments for `--source` flags.

                                            *taskbuffer.config_json_arg()*
taskbuffer.config_json_arg()
    Returns the JSON-encoded config string.

9. PERFORMANCE                                     *taskbuffer-performance*

                                                        *:TasksProfile*
:TasksProfile [start|stop|reset|report]
    Record opt-in stage timings and editor-wide scheduling delay.
    start:  Clear previous results and begin recording.
    stop:   Stop recording and display results.
    reset:  Clear results, preserving whether recording is active.
    report: Display results (also the default with no argument).
    Reports remain available through :messages or another report command.

Example: >
  :TasksProfile start
  :Tasks
  " Repeat a slow operation, switch away and back, or change filters.
  :TasksProfile stop
<
To capture setup(), set this before loading/configuring taskbuffer: >lua
  vim.g.taskbuffer_profile = true
<
With lazy.nvim, add "TasksProfile" to the plugin's cmd list so recording can
start before the first :Tasks. Use |--startuptime| for module loading and full
startup comparisons. Setup only installs lightweight lazy entry points. It does
not scan/read task sources, generate help tags, or start a background timer.
Plugin managers generate help tags; use `make helptags` for dev checkouts.

Timings are inclusive wall-clock milliseconds; rows overlap and must not be
summed. Count/total/mean/max cover the whole session. p95 uses the latest 256
samples per stage. Disabled recording has no timer or sample collection.

Task and project scans run concurrently. CPU processing yields between batches
(target: about 4 ms); async.slice measures uninterrupted work, while
render/parse/frontmatter/format timings include time spent yielded.
event_loop.delay measures excess delay over a 20 ms polling interval across
the editor, including other plugins and OS scheduling. It is not attribution
to taskbuffer and may miss short stalls.

Unchanged source metadata reuses parsed tasks; unchanged views reuse formatted
text. Display-only changes and tag queries reuse the snapshot without scanning.
Re-entry discovers external edits/new/deleted files. Source mutations force a
new snapshot. Hidden buffers cancel pending work; stale results are discarded.
Results update only their originating buffer and preserve cursors/views.

Programmatic results: >lua
  local profile = require("taskbuffer.profile")
  vim.print(profile.snapshot())
  print(profile.report())
<
For isolated startup and generated-vault benchmarks, run `make bench` from the
repository root. Python 3, Neovim, and ripgrep are required. Custom workload: >
  make bench BENCH_ARGS='--files 500 --tasks-per-file 20 --runs 20'
<
See docs/performance.md in the repository for benchmark interpretation,
working performance budgets, and LuaJIT sampling profiles.
